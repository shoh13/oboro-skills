# kataribe:video

台本と画面から、字幕・シーン・章・立ち絵が音声の実測長に同期して切り替わる単一HTML（`out/video.html`）と、文字起こし（`out/transcript.md`）を作る。話者はずんだもん・四国めたん・春日部つむぎ・雨晴はう・あんこもんから2人までで、行ごとに話者と表情を決める掛け合いの形式。

## 最初に行うこと（立ち絵素材の確認）

スキルを起動するたび、プロジェクトのファイルを書く前に、次を実行する（`<プラグインのルート>` と環境変数は「作る」を見る）。

```bash
uv run --project <プラグインのルート> kataribe assets
```

5人それぞれの素材の状態を1行ずつ出す。ネットワークに接続せず、zip を展開せず、キャッシュに書き込まない。素材なしの話者がいても終了コードは0。

| 状態（優先順） | 意味 |
| --- | --- |
| `キャッシュ済み` | キャッシュの manifest が定義と一致する。build はそのまま使う |
| `zip あり` | 素材の置き場所に、定義の名前で MD5 の一致する zip がある。build はネットワークに接続せず使う |
| `自動取得可` | 定義に `url` がある。build が配布元から取得する（ネットワークが必要） |
| `素材なし` | どれでもない。行に配布元のページ、zip の名前、置き場所のパスが出る。build は失敗する |

話者の決め方:

- 話者をユーザーに聞くときは、`素材なし` 以外の話者だけを候補にする。
- ユーザーが `素材なし` の話者を希望したら、`assets` の行に出た取得手順（配布元のページ、zip の名前、置き場所）を示す。入手するか別の話者にするかをユーザーが決めてから、台本を書く。入手したら `assets` をもう一度実行して確かめる。配布元のログインやパスワードを回避しない。

## 話者の口調

台本を書くとき、話者を変えて書き直すときは、次を基準にする。話者を変えるときは、一人称・語尾・呼び方まで全行を書き直す。

| 話者 | 一人称 | 語尾 | 例文（作例） |
| --- | --- | --- | --- |
| ずんだもん | ずんだもん、僕 | 〜のだ、〜なのだ | 「僕も試してみるのだ。結果が楽しみなのだ」 |
| 四国めたん | わたくし | 〜わ、〜わね、〜かしら、〜の | 「わたくしが説明するわ。まず全体を見ましょうか。難しくないの」 |
| 春日部つむぎ | あーし | 〜だよ、〜じゃん（公式の指定はなく、公式の人物紹介「ギャルの女の子」からの目安） | 「あーしが見てみたけど、これ便利じゃん。先に手順を確認しとくといいよ」 |
| 雨晴はう | 僕 | 〜です、〜ます（公式の自己紹介「現役看護師です！」の文体から） | 「僕が順番にお伝えします。ここは大切なところです」 |
| あんこもん | あんこもん | 〜もん、〜だもん | 「あんこもんは知らないもん。でも負けないんだもん」 |

一人称は VOICEVOX 公式サイトの各キャラクターの呼び方のページ、あんこもんの語尾は同サイトの紹介ページによる。例文は公式の台詞ではなく、口調を示すための作例。

## プロジェクトの形

```javascript
<project>/script.json    台本
<project>/scenes.html    画面（シーンごとの <section data-scene="シーンID">）
<project>/readings.json  読みの辞書（JSONのオブジェクト）
```

`script.json`:

```json
{
  "title": "動画のタイトル",
  "description": "概要欄に出す説明（任意。改行は保たれる）",
  "sources": [{"title": "出典のタイトル", "url": "https://example.com/"}],
  "chapters": [
    {"id": "c1", "title": "章のタイトル", "scenes": [
      {"id": "s1", "lines": [
        {"speaker": "四国めたん", "text": "1文ずつ書く"},
        {"speaker": "ずんだもん", "expression": "smile", "text": "話者は行ごとに決める"}
      ]}
    ]}
  ]
}
```

- 各行の `speaker`（必須）は話者で、`ずんだもん`、`四国めたん`、`春日部つむぎ`、`雨晴はう`、`あんこもん` のどれか。1本で使える話者は2人まで（3人目が出た行で lint と build が失敗する）。使える話者は、声（`src/kataribe/voices.py`）と立ち絵の定義の両方がある話者。その行は、その声で合成する。冒頭に `voice` は書かない（書くと、`speaker` のない行がエラーになる）。`speaker` のない地の文は、スライド（`oboro:kataribe-slides`）でだけ使える。
- 各行の `expression`（任意）は表情。省略すると `normal`。使える表情と立ち絵の表示は「立ち絵の素材」を見る。

`scenes.html` の `<section data-scene="s1">` が、台本の `scenes[].id` に対応する。

画面（`scenes.html`）は、字幕を繰り返す文字の置き場ではなく、図解として書く。そのシーンで説明する構造を、カード・フロー（矢印でつないだ段階）・比較（並べた列）・数値の強調・図版で見せ、`data-at` で説明の順に出す。

- `<img src="…">`（`<source>`、SVG の `<image href>` も）の相対パスは、プロジェクトのディレクトリからのパスで、`build` が data URI にして埋め込む（`out/` の場所によらず表示される）。`http(s)`・`data:`・`/` や `//` で始まる参照は、そのまま残す。ファイルがなければ、`lint` と `build` が `scenes.html` の行番号とパスを示して失敗する。
- 立ち絵は、ステージの上端から高さの54%より下に、左右の端寄り（中心は端から幅の約12%）に重なる。図の本体は、左右に幅の19%ほどの余白をとった列に置くことから始める（立ち絵の幅は話者の素材で変わる）。見出しなど上の45%に収まるものは、幅いっぱいに置ける。ステージは `overflow: hidden` なので、はみ出した図は切れても lint と verify では見つからない。`layout` で検査し（「配置の検査（layout）」）、問題の行を `shoot --at full` の画像で確かめる。
- 図は、同梱の部品の CSS（クラス名は `kt-` で始まる。「図の部品（kit）」）で、`<style>` を書かずに作れる。

## プロジェクトの場所と出力先

- 台本から作るときは、プロジェクト（`script.json`・`scenes.html`・`readings.json`）を置くディレクトリと、出力先のディレクトリを、ユーザーが指定していなければ、ファイルを書く前にユーザーに聞く。決めずに作り始めない（プラグインのディレクトリの中に勝手に作らない）。
- 作成先をユーザーに聞いて答えを得たら、そのディレクトリに書き込めるかを確かめてから確定する（例: `mkdir -p <作成先> && test -w <作成先>`）。書き込めなければ、理由を示して別の場所をユーザーに聞く。
- 出力先は、`build`・`shoot`・`verify`・`layout`・`mp4` の `--out <ディレクトリ>` で指定する（ないディレクトリは作る）。付けなければ `<project>/out`。以下の `out/` は、この出力先を指す。
- `build` で `--out` を付けたら、同じ出力を読む `shoot`・`verify`・`layout`・`mp4` にも同じ `--out` を付ける（付けないと `<project>/out` を探して失敗する）。
- 作り終えたら、出力先のパス（`video.html` など）をユーザーに伝える。

## 作る

プラグインのルートは、この `SKILL.md` のあるディレクトリから上へたどって、最初に `pyproject.toml` が見つかるディレクトリ（このスキルでは同じディレクトリ）。カレントディレクトリに関係なく、次のように実行する。

```bash
uv run --project <プラグインのルート> kataribe build <project> [--out <出力先>]
```

### 実行環境

- **仮想環境の置き場所:** `uv run` は既定でプラグインのルートに `.venv` を作るので、プラグインのディレクトリに書き込めない環境では失敗する。そのときは、この節以降のすべての `uv run` の前に `UV_PROJECT_ENVIRONMENT="$HOME/.cache/kataribe/venv"` を付け、`--frozen` を足して、スキルのディレクトリに書き込まずに実行する（例: `UV_PROJECT_ENVIRONMENT="$HOME/.cache/kataribe/venv" uv run --frozen --project <プラグインのルート> kataribe assets`）。
- **ネットワーク:** 初回は依存パッケージの取得に `pypi.org` と `files.pythonhosted.org` への接続が要る。
- **コマンドごとに要るもの:**

| コマンド | 要るもの |
| --- | --- |
| `assets`、`lint` | なし |
| `readings`、`build` | Docker（VOICEVOX）。`build` は、全行の音声がキャッシュにあれば不要 |
| `shoot`、`verify`、`layout`、`mp4` | ブラウザ（Google Chrome） |

- **サンドボックスで拒否されたとき:** Docker のソケットへの接続やブラウザの起動が拒否されたら、権限を回避しない。出力をプロジェクト内のファイルに保存するコマンドをユーザーに渡し、ユーザーの実行後に、そのファイルを読む。読みの確認・作成・撮影・検証を1回の依頼で済ませるときは、次をまとめて渡す（仮想環境の置き場所の指定が要る環境では、各行に同じ指定を付ける。`--out` を付けるなら、`readings` 以外のすべての行に同じ `--out` を付ける）。

```bash
K=<プラグインのルート>; P=<project>
uv run --project "$K" kataribe readings "$P" > "$P/readings.log" 2>&1
uv run --project "$K" kataribe build "$P" > "$P/build.log" 2>&1
uv run --project "$K" kataribe shoot "$P" --at full > "$P/shoot.log" 2>&1
uv run --project "$K" kataribe layout "$P" > "$P/layout.log" 2>&1
uv run --project "$K" kataribe verify "$P" > "$P/verify.log" 2>&1
```

- **大きな出力:** `readings.log` は台本の1行につき5〜6行になる。全行を台本と照らす作業は、読み取り専用のサブエージェントに任せて、誤りのある行だけを受け取る。

### build の動き

- 音声は、TTSアダプター（テキストを stdin、`--voice`、`--speed`、`--output` で WAV を出力する外部コマンド）で、文ごとに合成する。
- 既定のアダプターでは、`build` が起動したエンジンの URL を各行のアダプターに渡し、行ごとの Docker の確認を省く。
- 行ごとの音声（WAV）をキャッシュに保存する。合成に渡す文・声・話速・アダプター・アクセントの辞書の語がすべて一致する行は、合成せずにキャッシュの音声を使う。アダプターの識別は、kataribe のコンテナでは VOICEVOX のイメージのタグ、`KATARIBE_VOICEVOX_URL` ではエンジンの `/version`、`KATARIBE_TTS_CMD` ではコマンドの文字列。置き場所は `~/.cache/kataribe/tts`（`KATARIBE_TTS_CACHE` で変える。`off` で無効）。標準エラーに `音声: 213 行のうち、合成 3 行、キャッシュ 210 行` のように出す。全行がキャッシュにあれば、エンジンを起動しない。
- `build --no-cache` は、キャッシュを読まず書かずに全行を合成する。キャッシュに書き込めないときは、警告して、キャッシュなしで続ける。`KATARIBE_TTS_CMD` のアダプターの処理を、コマンドの文字列を変えずに変えたときは、キャッシュのディレクトリを消してから build する。
- 単一HTMLには、つないだ音声を AAC（48 kbps、m4a）にして埋め込む（`data:audio/mp4`）。ffmpeg は `imageio-ffmpeg` のもの（`KATARIBE_FFMPEG` で差し替え可）。変換できないときは build は失敗する。副産物の `audio.wav` と `mp4` は WAV のまま。
- 既定のアダプターは VOICEVOX（Docker）。Docker が動いている必要がある。初回はイメージを取得する。
- `KATARIBE_TTS_CMD` に別のアダプターコマンドを指定すると、差し替えられる（そのときは、読みを確かめる `readings` は使えない）。
- TTS が動いていないとき、build は失敗として終了し、`out/` を作らない（初回）。
- 出力（`video.html`、`transcript.md`、`--extras` のときは `extras/`）は、出力先と同じ場所（既定はプロジェクトの下）の一時ディレクトリ（`.kataribe-out-*`）に全部作ってから `out/` へ移す。途中で失敗したときは、`out/` は前回のまま。
- build が失敗しても、前回の `out/` はそのまま残る。前回の `out/video.html` があるときは、標準エラーに「前回の out/ は古いままです（今回の台本は反映されていません）」を添える（`lint` の失敗では出さない）。
- `--extras` なしで build し直しても、前回の `out/extras`、`out/mp4`、`out/frames` には触らない。
- `out/video.html` が16 MiB（16,777,216 バイト）を超えるときは、build は失敗する（ファイルを直接渡せる大きさに収めるため）。標準エラーに、実際のバイト数と上限を示す。前回の `out/` はそのまま残る。

## 立ち絵の素材

- build は、台本で使う話者ごとに、立ち絵の素材（PSD の入った zip）を用意し、MD5 で検証して、リポジトリの外のキャッシュ（既定は `~/.cache/kataribe/characters`。`KATARIBE_CHAR_CACHE` で差し替え）に置く。キャッシュがあれば取得しない。素材の置き場所は、環境変数 `KATARIBE_CHAR_SOURCES`、oboro の設定ファイル（setup-oboro が書く）の `kataribe.char_sources`、既定の `~/Documents/kataribe-assets` の順に決める（`kataribe assets` の `素材なし` の行に、決まった置き場所が出る）。ここに定義の `file` の名前で MD5 の一致する zip があれば、どの話者でもネットワークに接続せずに使う。なければ、ずんだもん・四国めたんは配布元（坂本アヒル氏）から取得し（ネットワークが必要）、キャッシュの `source.zip` に加えて、素材の置き場所にも `file` の名前で保存する（MD5 の違う同名のファイルがあれば上書きせず、保存できなくても build は続ける）。春日部つむぎ・雨晴はう・あんこもんは配布元がログインやパスワードを求めるので、使う人が落とした zip を素材の置き場所に置く。zip がなければ、build は配布元のページ、zip の名前、置き場所を示して失敗する。定義の `source` は、`file`（zip の名前）を持ち、自動で取得するなら `url`、手元の zip を使うなら `page`（配布元）を持つ。素材の状態は `kataribe assets` で確かめる（「最初に行うこと」）。
- 立ち絵の定義（話者ごとの表情とレイヤーの選び方）は `src/kataribe/characters/*.json`。表情は全員9種（`normal`、`smile`、`surprised`、`troubled`、`jito`、`panic`、`think`、`angry`、`cry`）で、既定は `normal`。素材に PSDTool の「*」がないグループは、定義の `choices` に挙げると「*」と同じく中の1つだけを選ぶ扱いになる（雨晴はうの目と眉）。立ち位置は定義の `side`（四国めたん・春日部つむぎ・雨晴はうは左、ずんだもん・あんこもんは右）。2人の `side` が同じなら、台本で後から出た人を反対側に置く。`KATARIBE_CHAR_DEFS` に別のディレクトリを指定すると、その定義を使う（開発・テスト用）。
- 台本で使った表情（と `normal`）のレイヤーだけを、縮小した PNG にして `out/video.html` に埋め込む（`#kataribe-cast`）。
- プレーヤーは、使った話者の立ち絵をステージの下に常に表示する（立ち位置は上の規則で決める。中央を向くように左右を反転する）。話している人はその行の `expression`（省略なら `normal`）、話していない人は最後に話した行の表情（まだ話していなければ `normal`）になる。見た目は時刻だけで決まるので、`shoot` と `mp4` の撮影にも、その時刻の表情で写る。口パクは、build 時に行ごとの WAV の音量（RMS）から 1/30 秒ごとに3段階（閉じ・半開き・開き）を計算してタイムラインの各行の `mouth` に入れ、プレーヤーは時刻からその段階を引いて、話している人の口だけを動かす（話していない人は閉じる）。閾値は yes の値（無音は RMS 300 未満、開く基準 0.2・0.5、閉じる基準 0.12・0.38、行の声のあるフレームの90パーセンタイルで正規化、1フレームだけの開閉は除く）。まばたきは、各話者が4秒ごとの区間に1回、0.12秒だけ目を閉じる（表情の目のレイヤーを閉じ目に替える）。閉じる時刻は話者ごとに決まり、時刻だけで決まる。閉じ目のない表情（`smile` など）ではまばたきしない。目印は `#kataribe-stage .kataribe-character[data-speaker][data-face][data-mouth][data-blink]`。
- 取得・MD5 の検証・PSD の展開・レイヤーの書き出しのいずれかに失敗したときは、build は失敗する（音声の合成の前）。前回の `out/` はそのまま残る。音声だけの動画にはしない。
- 台本の `expression` が、その話者の立ち絵の定義にないときは、lint と build が、場所と使える表情を示して失敗する。lint は素材を取得せず、定義だけで検査する。
- 素材と書き出した画像は、git にもスキルの配布物にも共有用の zip にも入れない（作者が素材の再配布を許していない）。素材の置き場所とキャッシュは、スキルのディレクトリの外に置く。利用は非商用に限る。

## 検査する（lint）

```bash
uv run --project <プラグインのルート> kataribe lint <project>
```

音声は合成しない（TTS も Docker も不要）。`build` も、TTS を呼ぶ前に同じ検査をする。成功すると、標準出力に `lint: 成功（警告 N 件）` の1行を出す（警告の本文は標準エラー）。

- 失敗（終了コード1）: `title` がない（空白だけも含む）、行の `speaker` がない、行の `speaker` が許可リスト（ずんだもん、四国めたん、春日部つむぎ、雨晴はう、あんこもん）にない、3人目の話者が出る、行の `expression` が空でない文字列でない、`script.json` の構造の誤り、章が1つもない、行が1つもない章、空の `text`、シーン ID・章 ID の重複、シーン ID・章 ID が空・空白だけ（重複した ID と、その場所を示す。大文字小文字だけが違うシーン ID は通り、`shoot` だけが失敗する）、台本のシーンに対応する `<section data-scene="…">` が `scenes.html` にない、同じ `data-scene` の `section` が `scenes.html` に2つ以上ある（ID と場所を示す）、`description` が文字列でない、`sources` の構造の誤り（`title`、`url` が文字列でない、`url` が `http`・`https` で始まらない、`url` にホスト名がない（`https://`、`http:///x` など。`localhost` やポート番号つきは通る））（エラーに項目の場所が出る）。
- 警告（続行）: `scenes.html` の `section`（`data-scene` が空のものを含む）が、台本のどのシーンにも対応しない（`警告: scenes.html の◯行目: …`）、1行が60字を超える字幕、読みが未登録の英単語（英字2文字以上で、行に `reading` がなく、`readings.json` の表記にも含まれないもの）、台本で使う話者が `kataribe assets` の `素材なし`（配布元のページ、zip の名前、置き場所を示す。失敗にはしないが、そのままでは `build` が失敗する）。
- 字幕の表示速度が1秒7.5字を超える警告は、音声の長さが要るので、`lint` では出さない。`readings` が音声クエリから計算した長さで事前に出し、`build` が音声合成のあとに実測の長さで出す（「字幕の表示速度」）。

## 読み

字幕と文字起こしには表示文（`text`）を使い、音声合成には「読み」を渡す。

- 行に `reading` があれば、その `reading` を、その行の音声合成にそのまま渡す（`text` の全体を置き換える）。`readings.json` はその行には使わない。
- 行に `reading` がなければ、`readings.json`（`{"表記": "読み"}`）の表記を、`text` の中で長い表記から順に読みへ置き換えて渡す。置き換えは1回だけで、置き換えた結果を再び置き換えない。大文字小文字は区別する。読みを空文字にすると、その表記は発音されない。
- `readings.json` の値は、読みの文字列のほか、`{"reading": "<カタカナ>", "accent": <整数>}` にできる（例: `{"TB": {"reading": "テラバイト", "accent": 3}}`）。置き換えには `reading` を使い、さらに、表記と発音がともに `reading` の語として、VOICEVOX のユーザー辞書に登録する。エンジンはその語を1語として、指定のアクセントで読む。`accent` はアクセント核（直後で音が下がる拍）の位置で、先頭の拍を1とし、0は平板。拗音（シャ・ディなど）は1拍、長音「ー」・促音「ッ」・撥音「ン」はそれぞれ1拍と数える。
- 語を登録すると、その前後の語の区切りが変わり、隣の漢字の読みが変わることがある（「テラバイト」だけを登録すると、「数テラバイト」の「数」が「カズ」になる）。隣の語と合わせて登録する（`"数テラバイト": {"reading": "スウテラバイト", "accent": 4}`）。登録したあとは、`readings` でその行の `エンジンの読み:` を確かめる。
- 次はエラー: `reading` か `accent` がない、`reading` がカタカナ（ァ〜ヴ）と「ー」以外の文字を含むか「ー」で始まる、`accent` が整数でない、`accent` が0から拍の数までの範囲にない、`reading`・`accent` 以外のキーがある、同じ `reading` に違う `accent` を指定した項目がある。
- ユーザー辞書は、既定の VOICEVOX を使うときだけ同期する（`KATARIBE_TTS_CMD` では同期しない）。`readings` は音声クエリの前に1回、`build` は最初に合成する行の前に1回同期する。kataribe が起動する Docker のコンテナでは、辞書をプロジェクトの語と一致させる（ほかの語は消す）。`KATARIBE_VOICEVOX_URL` のエンジンでは、語の追加と更新だけをして、消さない。
- 表記は、語の途中にも当たる（`"空の": "カラの"` は「架空の」の中にも当たり、「架カラの」になる）。当ててはいけない語は、長い表記として足す（`"架空の": "かくうの"`）。長い表記が先に当たるので、短い表記はその中には当たらない。
- `readings.json` の読みが文字列でない、行の `reading` が空、はエラー。
- 合成に渡す文は、`readings` も `build` も同じ規則で作る。`readings` で、実際に渡す文と、エンジンの読みを確かめられる（次の節）。

## 読みを確かめる（readings）

```bash
uv run --project <プラグインのルート> kataribe readings <project>
```

`build` が合成に渡す文（上の規則で作ったもの）を、VOICEVOX の `/audio_query` に渡し、エンジンが組み立てた読みと、音声クエリから計算した音声の長さを、行ごとに台本の表示文と並べて標準出力に出す。音声は作らず、`out/` も作らない。字幕の表示速度の超過は、標準エラーに警告する（終了コードは0のまま）。

- 読むのは `script.json` と `readings.json`。`scenes.html` はなくてよい（あれば `lint` と同じく検査し、誤りがあれば失敗する）。
- 行ごとに、`合成に渡す文:`、`辞書:`（置き換えた `readings.json` の項目を `表記→読み` で、当たった順に並べる。読みが空の項目は `（発音しない）`。当たった項目がない行と、行の `reading` を使う行には出さない）、`エンジンの読み:`、`アクセント:`、`音声の長さ（計算）:` を出す。
- `アクセント:` は、アクセント句を「/」で区切り、各句のアクセント核の拍の後に「'」を付け、ポーズを「、」で示す（例: `スウテ'ラ/バ'イトニ/タッ'シタノ`）。抑揚の誤りは、この行で探す。
- 合成に渡す文の片仮名語（3字以上）で、アクセント句の境界が語の中にあり、2拍以下の切れ端ができるときは、標準エラーに警告する（例: `警告: s1-4: 片仮名語「テラバイト」が、アクセント句の途中で区切られています（スウテラ / バイトニ）。readings.json に読みとアクセントを登録すると、1語として読みます`）。各部分が3拍以上の区切り（ローカル / インデックス など）は、複合語の境界として警告しない。直し方は、その語を `readings.json` に `{"reading", "accent"}` の形で登録して、`readings` をもう一度実行する。
- 行の順・文・声は `build` と同じ。空になった文も、`build` と同じく渡す（エンジンが返した読みを、そのまま出す）。
- 既定の VOICEVOX（Docker。`KATARIBE_VOICEVOX_URL` があれば、そのエンジン）を使う。Docker が動いていなければ、失敗する（終了コード1）。
- `KATARIBE_TTS_CMD` で独自の TTS を使っているときは、読みを取れないので、失敗する（読みを返すのは VOICEVOX の音声クエリだけ）。独自の TTS の読みは、その TTS の仕様で確かめる。
- 限界: この表は、エンジンが組み立てた読み（拍ごとのカタカナ）を見せるだけで、読みが文脈に合っているか、アクセントや抑揚が自然かは、自動では判定できない。読みが正しいことを保証しない。

### 読みを直す手順（作るときに行う）

1. `build` の前に `readings` を実行する（VOICEVOX が必要）。
2. 出力の**全行**を、台本の表示文と照らして読む。漢字の読み違い、助詞（「は」「へ」など）、数字・英字・記号、固有名詞を探す。`辞書:` の行で、表記が語の途中に当たっていないかも確かめる。片仮名語の区切りの警告と `アクセント:` の行で、抑揚の誤りを探し、語を `{"reading", "accent"}` の形で登録して直す。
3. 誤りがあれば、`readings.json` に「表記」と「読み」を足すか、その行に `reading` を書いて直す。表示文（`text`）は変えない（字幕と文字起こしに出るため）。
4. 直したら、`readings` を全行でもう一度実行し、2〜3を、誤りがなくなるまで繰り返す。直した読みが、同じ表記を含む他の行にも効いていないかを、その結果で確かめる。
5. 利用者には、「エンジンが組み立てた読みを、全行、台本と照らして確かめた」と伝え、「アクセント・抑揚・文脈に合った読みは保証しない。音声を聴いて確かめてほしい」と添える。

## 字幕の表示速度

字幕は1秒7.5字以内にする。`字数 ÷ 音声の長さ` が7.5を超える行は、次の2か所で同じ判定と文言の警告になる。字数は句読点を含む表示文（`text`）の文字数。

- `readings`（音声合成の前）: 長さは、音声クエリの拍ごとの `consonant_length`・`vowel_length`、`pause_mora`、`prePhonemeLength`・`postPhonemeLength` を `speedScale` で割って音素ごとにフレーム（256/24000 秒）へ丸めて足したもの。疑問文の句（`is_interrogative`）は、末尾の拍が有声なら、エンジンが足す上げ調子の0.15秒も入れる。
- `build`（音声合成の後）: 長さは、合成した音声の実測。

台本を書いたら、`build` の前に `readings` で超過を見つけて直す。直し方の目安:

- 英字の製品名を並べると、文字数に対して拍が少なく（Cassandra は9字で5拍）、速度が上がる。並べる数を減らすか、言葉を足す。
- 小書きの仮名（ィ・ョ・ャなど）を含む片仮名語（パーティション、シャーディング）も、小書きの仮名が拍にならないので、字数に対して拍が少ない。漢語に言い換えると（「ルール」→「規則」、「受け持つ」→「担当する」）、字数あたりの拍が増えて速度が下がる。
- 読点は1字で約0.43秒の間が入るので、速度を下げる。
- 行を2つに分けて直すと、そのシーンの、それより後の行番号がずれる。分けたら、`scenes.html` の `data-at`・`data-out`・`data-focus` も直す。
- 表示文だけを短くして `reading` に元の文を入れる直し方は使わない。字幕と音声が食い違う。

## プレーヤーの操作

- 再生・一時停止、字幕の表示切替。
- 再生位置のシークバー: ステージの直下、字幕の上に置く（字幕の行数が変わってもバーが動かないため）。ドラッグで任意の位置へ移動でき、再生中も止まらない。現在時刻と全体の長さを両脇に出す。バーにフォーカスがあっても、← → は行の移動にする（ほかのキーは、バー自身の既定の動作）。MP4 では隠す。目印は `#kataribe-seek-bar`。
- モバイル表示（幅600px以下）: 操作ボタン（前へ・再生/一時停止・次へ・字幕・文字起こし）は文字をアイコンに替え、タップしやすい44px四方以上にする。文字は画面に出さないだけで、ボタンの名前としては残る（スクリーンリーダー向け）。再生中は一時停止のアイコンに替わる。広い画面では従来どおり文字のボタン。
- 再生速度: 0.5倍、0.75倍、1倍、1.25倍、1.5倍、2倍から選ぶ（既定は1倍）。字幕・シーン・立ち絵の口パクは再生時刻で決まるので、どの速度でもずれない。目印は `#kataribe-rate`。
- 文の前後移動: 「前へ」「次へ」ボタン、またはキー ← →。「次へ」は1つ後の行の先頭へ、「前へ」は1つ前の行の先頭へ移動する（先頭の行で「前へ」は時刻0へ戻り、最終行で「次へ」は動かない）。再生中に移動しても再生は続く。
- キー操作: 次の表のとおり。キーの定義は `player/keys.js` の1つの表で、キー一覧も同じ表から作る。`?` キーか、画面の右下に常に出る「?」のボタン（`#kataribe-keys-open`）で、キー一覧を開閉する（既定は閉じている。Esc、閉じるボタン、一覧の外のクリックでも閉じる。開いている間は `?` 以外のキーは効かない）。目印は `#kataribe-keys`（`<dialog>`）。キー一覧と「?」のボタンは、shoot・mp4 には写らない。

| キー | 操作 |
| --- | --- |
| Space、K | 再生・一時停止 |
| J ／ L | 5秒戻る ／ 5秒進む |
| ← ／ → | 前の行 ／ 次の行 |
| ↑ ／ ↓ | 前の章 ／ 次の章（↑ は、章の先頭から2秒を超えていればその章の先頭、2秒以内なら前の章の先頭。最後の章で ↓ は動かない） |
| Home ／ End | 先頭 ／ 最後の行の先頭 |
| 0〜9 | 全体の0%〜90%の位置 |
| [ ／ ] | 再生速度を1段階下げる ／ 上げる（`#kataribe-rate` の選択肢の順。端では変わらない） |
| C | 字幕の表示切替（字幕ボタンと同じ） |
| T | 文字起こしの開閉（文字起こしボタンと同じ） |
| ? | キー一覧の開閉 |

- 英字キーは大文字・小文字を区別しない。Ctrl・Meta・Alt つきのキーと、Shift つきのキー（`?` を除く）は奪わない。入力欄（input・textarea・select（再生速度の選択を含む）・contenteditable）にフォーカスがあるときは奪わない（再生位置のバーの ← → を除く）。ボタン・リンクにフォーカスがあるときの Space は、そのボタン・リンクの既定の動作にする。押し続けたときに繰り返すのは J・L・矢印・[ ] だけ。↑ ↓ Home End Space は、ページのスクロールに使わない。マウスやタッチで操作したボタン・再生位置のバー・再生速度の選択は、操作のあとフォーカスを外す（キーで操作したときは残す）ので、マウスで操作した直後もキー操作が効く。対応するボタンと再生速度の選択には `aria-keyshortcuts` を付ける。
- 章バー: 章ごとの区間（幅は章の長さに比例）が並び、章をクリックするとその章の先頭へ移動する。現在の章は `aria-current="true"` で示す。目印は `#kataribe-chapter-bar` の子の `[data-chapter-id]`。
- 文字起こし: 「文字起こし」ボタンで開閉する（既定は閉じている）。行をクリックすると、その行の先頭へ移動する。現在の行は `aria-current="true"` で示す。目印は `#kataribe-transcript` の子の `[data-line-id]`（閉じていても全行が DOM にある）。

## 概要欄

プレーヤーの下に常時表示する。台本の `description`（HTML としては解釈せず、文字列のまま表示）、`sources`（リンクとして表示）、使った声のクレジット（行の `speaker` に出た声のぶん。台本で初めて出た順。例: `VOICEVOX:四国めたん`、`VOICEVOX:ずんだもん`）、利用条件（VOICEVOX ソフトウェア利用規約と、使った声のキャラクターの規約へのリンク。ずんだもん・四国めたん・あんこもんなら東北ずん子・ずんだもんプロジェクト 音源利用規約、春日部つむぎなら VOICEVOX「春日部つむぎ」利用規約、雨晴はうなら公式サイト）を出す。`description` と `sources` がなければ、その部分は出さない（`description` が空文字、または前後の空白（全角スペースを含む）を除いて空になるときも、未指定として扱い、見出しを含めて出さない。エラーも警告も出ない）。リンクは別タブで開く。目印は `#kataribe-about` と、その中の `[data-about="description"|"sources"|"credits"|"terms"]`。

## シーンのスクリーンショット（shoot）

```bash
uv run --project <プラグインのルート> kataribe shoot <project> [--at start|mid|end|full|changes] [--out <出力先>]
```

先に `build` して `out/video.html` を作っておく。シーンごとに、ステージ（シーンの表示領域）のスクリーンショットを、`out/frames/<シーンID>-<at>.png` に出力する。`--at` を変えると名前が変わるので、上書きされない（同じ `--at` で撮り直すと置き換わる）。

- `--at` の既定は `end`。撮る時刻は、そのシーンの先頭行（`start`）、中央行（`mid`）、最終行（`end`）の開始から0.3秒後。中央行は、行の列の中ほどで、偶数のときは後ろ側を選ぶ。行が0.6秒より短いときは、その行の中央を撮る（前後の行に食い込まないため）。
- `--at full`: シーンごとに、表示が最も多い状態の行（次の行で消える要素がある行と、最後の行）を撮る。重ねたパネル（「行単位の出現」）の途中の状態も撮れるので、図のはみ出しと立ち絵との重なりは、これで確かめる。
- `--at changes`: シーンごとに、見た目（`data-at`・`data-out` による表示と、`data-focus` による強調）が前の行と変わる行を、先頭の行を含めてすべて撮る。出現の順を確かめるときに使う。枚数は行数に近くなる。
- `full`・`changes` の画像は、`out/frames/<full|changes>/<シーンID>-line<行番号（2桁に0埋め）>.png`。撮るたびに、そのディレクトリの `*-line*.png` を消してから撮る（台本の行が変わると、前回の行番号の画像が今回の行を指さなくなるため）。撮る時刻は、ほかの `--at` と同じく、その行の開始から0.3秒後。表示と強調は、`video.html` の要素の属性から、「行単位の出現」の規則（祖先の規則を含む）で計算する。
- ブラウザは、Google Chrome を既定にし、使えなければ Playwright Chromium を使う。どちらも使えないときは、それぞれについて、未導入（入れ方を示す）か、入っているが起動を拒否された・起動に失敗した（理由を示す）かを出して失敗する。開いたブラウザが単一HTMLの音声（AAC）を再生できないとき（Playwright Chromium など）は、Google Chrome を入れるよう示して失敗する（`verify`、`mp4` も同じ）。
- シーンIDが、ファイル名に使えない（`.`、`..`、`/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|`、制御文字を含む、末尾が `.` か空白。空は `lint`・`build` が先に失敗する）とき、または、大文字小文字を無視すると同じになるシーンID（`Intro` と `intro`）があるときは、何も出力せずに失敗する（画像が上書きされるため）。
- 再生位置の移動が5秒以内に終わらないときは、待ち続けずに失敗する。
- 撮影のときだけ、画面の CSS の `transition` と `animation` を無効にして、完了状態（最終の見た目）にする（`transition` は時間0、`animation` は時間0・遅延なし・1回・終了状態を保持。無限に繰り返すものは最初の1周の終わりの状態）。単一HTML（`out/video.html`）の再生では、そのまま動く。
- `out/frames` に、今回のシーンに対応しない `<シーンID>-<start|mid|end>.png` があると、標準エラーに `警告: out/frames の … は、今回のシーンに対応しません（古い画像です）` を出して続行する（終了コードは0）。ファイルは消さない。他のファイルには触れず、警告もしない。

## 行単位の出現（scenes.html の属性）

`<section data-scene="…">` の中の要素に、次の属性を付けると、行に合わせて変化する。行は、そのシーンの中の0始まりの番号（先頭の行が0）で指す。JavaScript は書かない。

- `data-at="n"`: n 行目から表示する（それまでは見えない）。
- `data-out="n"`: n 行目で消える。`data-at` がなければ、0行目から表示して、n 行目で消える。
- `data-focus="n,m"`: 指定した行で強調する（カンマ区切りで複数）。強調する要素に輪郭の目印が付き、同じ親の中の、他の `data-focus` を持つ要素は薄くなる。どの兄弟も強調していない行では、何も変わらない。
- 祖先の要素（`section` の中で `data-at`・`data-out` を持つもの）が消えている間は、子も消える（子の `data-at` の行が来ていても見えない）。親で消せば、子に同じ `data-out` を書く必要はない。
- 消えている要素も、場所は残る（周りの要素は動かない）。どの時刻へシークしても、見た目は、その時刻の行だけで決まる。
- 同じ場所で図を入れ替えるときは、パネルを1つのグリッドのセルに重ね（部品の `kt-stack`）、`data-out` と `data-at` で切り替える。重ねた領域の高さは、いちばん高いパネルに合う。

```html
<div class="kt-stack">
  <div class="kt-panel" data-out="5"><p data-at="2">0〜4行目の図（この段落は2行目から）</p></div>
  <div class="kt-panel" data-at="5">5行目からの図</div>
</div>
```

## 図の部品（kit）

`build` は、図の部品の CSS（`player/kit.css`。クラス名は `kt-` で始まる）を、`video.html` とスライドの図に埋め込む。`scenes.html` に `<style>` を書かずに、クラスだけで図を作れる。部品の規則は `#kataribe-stage` の中だけに効く。`scenes.html` の `<style>` で上書きするときは、同じく `#kataribe-stage .kt-card` のように `#kataribe-stage` を前に付ける（付けないと、部品の規則のほうが強い）。色は CSS 変数（`--kt-accent`・`--kt-good`・`--kt-bad`・`--kt-info`、背景用の `--kt-*-bg`、`--kt-card`）で、ダークモードでは明るい色に切り替わる。

`section` に `kt-scene` を付けると、文字の大きさがステージの幅に比例する（余白と枠を除いたステージの内側の幅の1.5%）。プレーヤーの幅、shoot、mp4、スライドの図で、折り返しの位置がそろう。

| クラス | 用途 |
| --- | --- |
| `kt-scene` | section に付ける。縦に並べる配置と、ステージの幅に比例する文字の大きさ |
| `kt-tag` | 見出しの上の小さい行（章・節の名前） |
| `kt-title` | シーンの見出し（中に `kt-stamp` を置ける） |
| `kt-body` | 本文の列。左右に19%の余白を取り、立ち絵を避ける |
| `kt-stack` | 子を1つのセルに重ねる（`data-out`・`data-at` での入れ替え）。`kt-body` と同時に付けられる |
| `kt-panel` | `kt-stack` の中の1枚（縦に並べる） |
| `kt-row` ／ `kt-col` | 横に並べる（折り返し・中央揃え） ／ 縦に並べる（中央揃え） |
| `kt-card`（`kt-good`・`kt-bad`・`kt-info`） | 説明の札。中の `<b>` は強調色 |
| `kt-node`（`kt-hot`・`kt-new`） | 構成要素の箱。`<small>` で補足を下に書く |
| `kt-key` | 等幅の囲み（キー・値・ID） |
| `kt-chip`（`kt-strong`・`kt-bad`） | 丸い札 |
| `kt-arrow` | 矢印の文字 |
| `kt-big` | 大きい強調の文。`<small>` で補足 |
| `kt-note` | 小さい注記 |
| `kt-stamp`（`kt-ok`・`kt-ng`） | 傾いた印（採用・失敗など） |
| `kt-bars` | 棒グラフ。子の `<i style="height:…%">` が1本、`<i class="kt-hot">` は警告色 |
| `kt-table` | 表 |

<section data-scene="s1" class="kt-scene">
  <div class="kt-tag">第1章 ／ 分割</div>
  <h2 class="kt-title">キーの範囲で分割する <span class="kt-stamp kt-ng" data-at="4">失敗</span></h2>

    <div class="kt-panel" data-out="3">

## 配置の検査（layout）

```bash
uv run --project <プラグインのルート> kataribe layout <project> [--out <出力先>]
```

先に `build` して `out/video.html` を作っておく。`shoot --at full` と同じ行（次の行で消える要素がある行と、最後の行）を、同じ時刻（行の開始から0.3秒後。`transition` と `animation` は完了状態）で表示し、次の2つを測る。問題は1件1行で標準出力に出す。問題がなければ `layout: OK` を出して終了コード0、1件でもあれば `layout: NG（n 件）` を出して終了コード1。

- はみ出し: 図が、ステージの表示領域（枠線の内側。越えた部分は `overflow: hidden` で切れる）から1pxを超えて出ている。出た辺（左・右・上・下）と、その px を示す。
- 立ち絵との重なり: 図が、立ち絵の canvas の不透明な部分に重なっている。canvas を4px四方の区画に分け、アルファが128以上の画素を含む区画を不透明として、図が覆う区画の数を示す。図の縁から1px内側で数え、ステージの外の区画は数えない。canvas の矩形に入っても、透明な部分だけに掛かる図は問題にしない。

```text
s4 の 4行目: <div.k-shelf> が、ステージの右に 18px はみ出しています
s17 の 9行目: <div.k-card「Cassandra／Riak: ゴシ…」> が、立ち絵（ずんだもん）と重なっています（12 区画）
```

- 測るのは、その行のシーンの `section` の中で、`visibility` が `visible`、祖先を含めた `opacity` が0より大きく、大きさが0でないもの。背景か枠のある要素、`img`・`svg`・`canvas`・`video`、文字（折り返した行ごとの矩形）を測る。祖先の `overflow` で切れて見えない部分は除く。`section` 自身の背景、疑似要素、`outline`、`box-shadow` は測らない。`svg` は全体を1つの矩形で、`transform` した要素は外接する矩形で測る。
- 行番号は、シーンの中の0始まりの番号（`data-at` と同じ）。`out/frames/full/<シーンID>-line<行番号>.png` と対応する。
- 要素は `<タグ#id.クラス「中の文字の先頭20文字…」>` で示す。文字は、背景か枠のある最も内側の祖先として示す（なければ親）。同じ要素の同じ問題は、シーンごとに1回、最も大きい行（同じなら先の行）で示す。入れ子の要素が同じ問題を持つときは、最も内側だけを示す。
- 幅か高さが2px以下の図（細い線など）は、重なりとして出ない。ブラウザの選択と、起動できないときの失敗は `shoot` と同じ。`out/video.html` がなければ、ブラウザを開く前に失敗する。
- `build` と `lint` は、次を失敗にする（`scenes.html` の行番号、シーンID、要素、属性を示す）: 行番号が、そのシーンの行数以上（存在しない行）、`data-out` が、同じ要素の `data-at`（なければ0）以下、値が0以上の整数でない（`data-focus` は、整数のカンマ区切り）。検査するのは、台本にあるシーンの `section` の中の要素だけで、`section` 自身の属性や、`section` の外の要素は検査しない。

## 進行変数（CSS 変数）

各シーンの `<section data-scene="…">` に、次の CSS 変数が、0から1の値で設定される（再生位置に応じて更新される）。

- `--p`: そのシーン全体の進行。
- `--lp`: 現在の行の進行（現在のシーンだけ。前のシーンは1、後のシーンは0）。
- `--gp`: 行後の間の進行。行の間に無音を入れないので、いつも0。

## 再生検証（verify）

```bash
uv run --project <プラグインのルート> kataribe verify <project> [--out <出力先>]
```

先に `build` して `out/video.html` を作っておく。ヘッドレスの Chrome（なければ Playwright Chromium）で、動画を実時間で最後まで再生し（倍速にしない。動画の長さと同じだけかかる）、次の7項目を検証する。結果は `① 名前: OK` または `① 名前: NG` と理由（最大5件）を標準出力に出し、すべて OK なら終了コード0、1つでも NG なら1。

1. 再生が最後まで進む（動画の長さ+10秒待っても `ended` にならなければ NG）。
2. 全シーンが、台本のシーンの順に表示される。
3. 各行の字幕が、その行の時間帯（前後0.3秒）に表示される。字幕が出なかった行も NG。
4. 章バー（`#kataribe-chapter-bar` の `[data-chapter-id]`）の数と、文字起こし（`#kataribe-transcript` の `[data-line-id]`）の数が、台本の章と行の数と一致する。
5. 各行の中（行の端の0.01秒を除く）で、`data-at`・`data-out` を持つ要素の `visibility` が、その要素と、`data-at`・`data-out` を持つ祖先（`section` の中）の規則から計算した期待と一致する。サンプルが1つも取れなかった行（要素のあるシーンの行）は、「検証できませんでした」と標準エラーに警告し、失敗にはしない。
6. 進行変数 `--p`・`--lp` が0〜1の範囲にあり、シーン内で `--p` が減らない。
7. 各話者の立ち絵の表情（`data-face`）と口の段階（`data-mouth`）が、タイムラインから計算した、その時刻（前後0.05秒のどこか）の期待と一致する。話している人はその行の表情と `mouth` の段階、話していない人は最後に話した行の表情で口は閉じ。表情と口は別々に比べる（行の境目では、表情が先に変わり、口は行の開始まで閉じたままになりうる）。まばたきは見ない。

観測は、再生中の約16ミリ秒ごとの DOM・`computed style`・CSS 変数・`audio` の状態だけで行い、プレーヤーに検証用のフックは持たない。台本が不正なときは、`lint` と同じエラーで失敗する。`out/video.html` がなければ、ブラウザを開く前に失敗する。

## 副産物（build --extras）

```bash
uv run --project <プラグインのルート> kataribe build <project> --extras [--out <出力先>]
```

MP4 化向けに、`out/extras/` へ次を出す（付けなければ出さない。毎回指定する）。

- `audio.wav`: 全行をつないだ音声。
- `captions.vtt`: 行ごとの字幕（WebVTT）。
- `timeline.json`: タイムライン（`duration`、`chapters`、`scenes`、`lines`）に、`title`、`credit`（使った声のクレジットの配列。声が1つでも配列）、`sources`（出典）を足したもの。
- `TERMS.txt`: 利用条件ファイル。クレジットと、VOICEVOX と使った声の規約へのリンク。**音声を配るときは必ず添える。**

## MP4（mp4）

```bash
uv run --project <プラグインのルート> kataribe mp4 <project> [--size 1280x720|1920x1080] [--fps 24|30|60] [--out <出力先>]
```

先に `build --extras` しておく（`out/extras/` と `out/video.html` が要る）。既定は 1280x720・30fps。`out/mp4/video.mp4` と、同梱の `out/mp4/TERMS.txt` を出す。

- 映像は、`out/video.html` を headless で開き、フレームごとの時刻へシークして撮影し、ffmpeg で `out/extras/audio.wav` と結合して作る。行単位の出現・消去・強調・進行変数が、そのまま映像に出る。実時間はかからないが、動画の長さ×fps の枚数を撮るので、長い動画ほど時間がかかる（進捗を標準エラーに出す）。
- 撮影のときだけ、画面の CSS の `transition` と `animation` を、`shoot` と同じ規則で無効にして、完了状態（最終の見た目）にする（実時間で進む動きの途中が、映像に入らないようにするため）。単一HTMLの再生では、そのまま動く。
- 画面の下に、その時刻の字幕を焼き込む。コントロール・章バー・文字起こし・概要欄は映らない。
- 末尾に、5秒のクレジット画面（題名、声のクレジット、出典）を付ける。映像の長さは、音声の長さ＋5秒。
- ffmpeg は、`imageio-ffmpeg`（uv が入れる）のものを使う。`KATARIBE_FFMPEG` にパスを指定すると差し替えられる。取得できないときは失敗する。
- 副産物がない、`out/video.html` がない、副産物と `out/video.html` の内容が食い違う（`build --extras` をし直す）、ブラウザが起動できない、ffmpeg が失敗した、ときは、失敗として終了する。
