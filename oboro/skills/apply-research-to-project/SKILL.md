<callout icon="🔀" color="purple_bg">
完了済みの調査記録から、親プロジェクトが今後も参照する結論、判断理由、完了条件、対象外、次の行動だけを抽出し、ユーザー確認後に根拠へ遡れる形で反映する。
</callout>

## 開始条件

- ユーザーが、反映元となる完了済みの調査記録を指定している。
- 調査記録から親プロジェクトを特定できるか、ユーザーが対象プロジェクトを指定している。
- 調査が未完了、親が不明、複数候補がある、または関係が曖昧なら反映を開始せず確認する。

## 完了条件

- 親プロジェクトだけで、持続する結論、判断理由、完了条件、対象外、次の行動が分かる。
- 詳細な証拠、引用、調査過程、未確認仮説は元の調査記録に残り、親から参照できる。
- 既存方針との重複・矛盾・変更点が明示されている。
- 親ページ更新、子タスク作成、元記録の状態変更は、ユーザーが個別に承認した項目だけ実行されている。
- 解決済みの対象プロジェクトと反映方法に従って更新され、別の調査や次工程を開始せずユーザーへ制御が返されている。

## 共通実行コンテキスト

開始時に次の7項目を解決または継承し、`artifact-destination`へそのまま渡す。

- \*\*環境：\*\*Lore、Notion、Repo、Issue trackerなど、調査記録と親プロジェクトが存在する実行環境。
- \*\*対象：\*\*完了済みの調査記録、候補となる親プロジェクト、反映候補。
- \*\*基準保存先：\*\*元記録の親子関係またはユーザー指定から得たプロジェクトの起点。
- \*\*適用ポリシー：\*\*プロジェクト規則、共有範囲、機密性、子タスク・状態変更の規則。
- \*\*確認済み事項：\*\*承認済みの反映対象、公開範囲、更新方法、子タスク作成、状態変更。
- \*\*作業範囲：\*\*参照してよい調査記録と、更新してよい親プロジェクト・関連項目。
- \*\*禁止範囲：\*\*新しい調査、未確認仮説の昇格、未承認の転記・子タスク・状態変更、ページ全体の整形。

継承済みの値は上書きせず、同じ対象・保存先・確認を再解決しない。共通条件が不足または競合した場合は、解決するまで反映しない。

## 合成Contract

### artifact-destination

- \*\*条件：\*\*常時。反映案を確定する前に1回だけ呼ぶ。
- \*\*渡すもの：\*\*共通実行コンテキスト7項目、成果物種別「調査結果のプロジェクト反映」、元の調査記録、親プロジェクト候補、必要な操作種別。
- \*\*受け取るもの：\*\*対象プロジェクト、親ページの更新方法、必要な場合の子タスク作成先と状態変更方法、確認要否、判断根拠、更新された共通実行コンテキスト。
- \*\*副作用：\*\*なし。対象と反映方法の決定だけを行い、内容抽出、反映案作成、書き込みは行わない。
- \*\*不足時：\*\*親候補、親子関係、更新方法、公開範囲が一意に決まらない地点で停止し、子が必要な確認だけをユーザーへ返す。
- \*\*競合時：\*\*元記録と親の共有範囲、ユーザー指定、適用ポリシー、作業範囲、禁止範囲が衝突したら停止し、競合内容と再解決に必要な選択をapply-research-to-projectへ返す。

## 責務境界

- このSkillは完了済みの調査記録を反映する。新しい問いを調べるために`research`や`evidence-research`を呼ばない。
- 調査記録に不足や未確認仮説があっても補完調査を始めず、未決・保留・追加調査候補としてユーザーへ返す。
- apply-research-to-projectが持続する情報の抽出、反映案の作成、承認済み変更の書き込みを所有する。`artifact-destination`は対象プロジェクトと反映方法を決めるだけである。
- 子タスク作成と元記録の状態変更は、親ページ更新とは別の承認対象であり、承認されても次工程を自動開始しない。

## 反映対象

| 調査内の情報 | 親での反映先 |
| --- | --- |
| 確定した結論・方向性 | 目的・方針 |
| 判断理由・比較結果 | 決定ログ |
| 成功条件・卒業条件 | 完了条件 |
| やらない範囲 | 対象外 |
| 後で扱う内容 | 棚上げ・保留 |
| 実行が必要な内容 | 次の行動・子タスク候補 |
| 証拠・引用・詳細 | 元の調査記録への参照 |

## 手順

1. 完了済みの調査記録と親プロジェクト候補を読み、調査の完了状態と親子関係を確認する。
2. 共通実行コンテキストを組み立て、`artifact-destination`を1回だけ呼んで対象プロジェクトと反映方法を解決する。不足または競合なら書き込み前で停止する。
3. 調査記録から、持続する結論、判断理由、完了条件、対象外、次の行動だけを抽出する。一時的なメモ、引用全文、調査過程、未確認仮説は除外する。
4. 親の既存内容と比較し、追加、更新、重複、矛盾、既存方針の置換候補へ分類する。
5. 親ページの変更、子タスク候補、元記録の状態変更候補、既存方針との衝突を分けた反映案を作る。
6. 転記する具体的な内容、変更先、根拠、公開範囲の変化を示し、ユーザー確認を得る。子タスクと状態変更は個別に確認する。
7. 承認された項目だけをapply-research-to-project自身が外科的に反映し、各判断から元の調査記録へ辿れる参照を残す。
8. 親だけで「なぜ」「どこまで」「完了とは何か」「次に何をするか」が分かることを検証し、次工程を開始せずユーザーへ制御を返す。

## 停止時に返すもの

- 不足・競合・未確認仮説の内容。
- 反映できる確定済み範囲と、反映できない理由。
- 必要なユーザー確認または再開条件。
- 追加調査が必要な場合は候補として示すだけにし、自動開始しない。

## 判断基準

- 調査結果を短くするのではなく、持続する意思決定と運営情報へ変換する。
- 詳細は元の調査記録、プロジェクト運営に必要な方針は親へ置く。
- 既存の決定を変える場合は上書きせず、旧方針、新方針、変更理由を示す。
- 次の行動は、具体的な成果と完了条件がある場合だけ子タスク候補にする。
- 未確認の内容は決定事項ではなく、未決・保留・追加調査候補として扱う。
- 親の既存スタイルと用語を守り、目的と無関係な整形を混ぜない。

## 禁止事項

- `research`または`evidence-research`を呼んで新しく調査する。
- 調査全文、引用、ログ、途中の仮説を親へ丸ごとコピーする。
- 未確認仮説を決定事項へ昇格する。
- 既存方針を説明なく上書きする。
- 未承認の親更新、子タスク作成、元記録の状態変更を行う。
- 狭い閲覧範囲の内容を、確認なしにより広い親へ転記する。
- `artifact-destination`を複数回呼ぶ、または継承済みの対象・保存先・確認を再解決する。
- 反映と同時にページ全体の整形、別の調査、次工程を開始する。

## 検証

- 起動主体がユーザー起動のままである。
- 本文の実呼び出しとRelationが`artifact-destination`だけで一致する。
- 共通実行コンテキスト7項目と呼び出しContract 6項目がある。
- 更新対象と書き込み方法が`artifact-destination`の結果と一致する。
- 親に追加した各判断が、元記録の確定済みの根拠へ遡れる。
- 未確認事項が決定事項へ混ざらず、既存方針との重複・矛盾・変更が明示されている。
- 承認範囲、公開範囲、子タスク、状態変更が個別の確認と一致する。
- 新しい調査や次工程を開始せず、ユーザーへ制御を返している。
