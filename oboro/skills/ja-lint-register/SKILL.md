# ja-lint ルール登録

`ja-lint`（PostToolUse/Stopフックで日本語文書を検査する仕組み。設計はagent-ops-kitリポジトリのREADMEのja-lintセクション参照）へ、新しい検出ルールを1本登録する手順。

## 手順

1. **指摘を具体化する**: ユーザーの一言（「この表現やめて」等）から、実際に問題視された文（陽性の実例）を特定する。ユーザーが直接文を示していなければ、直前の会話・差分から該当文を探す。**陽性の実例が手元に無い状態では登録しない**（下記「登録しない場合」参照）。
2. **正規表現化する**: 表現そのものではなく、表現が属する**パターン**を正規表現にする。語のみの置き換えでは同じ問題が別の語形で残るため、パターンの本質（何が問題か）を捉える。
3. **重複確認する**: `$JA_LINT_HOME/rules.jsonl`（既定 `~/.ja-lint/rules.jsonl`）を読み、既存ルールとパターン・対象が重複していないか確認する。重複していれば新規登録せず既存ルールを使う。
4. **good例を作る**: 禁止だけでなく、書き直しの方向を示す例文を1件以上作る（`good`フィールド）。無いと不自然な回避表現を招くため必須。
5. **陰性の実例を集める**: 誤検知しそうな正当な表現の実例を、実際のコーパスから探す（`rg`でリポジトリやプロジェクトのドキュメントを横断検索する）。正規表現が引っかかってはいけない正当な用例を最低2〜3件集める。
6. **`--test-rule`**<b> で実測する</b>:
   ```javascript
   python3 $JA_LINT_HOME/scripts/ja_lint.py --test-rule \
     --pattern '<正規表現>' \
     --good '<書き直し例1>' --good '<書き直し例2>' \
     --match '<陽性の実例>' \
     --nomatch '<陰性の実例1>' --nomatch '<陰性の実例2>' ...
   ```

   <p>
   全てPASSするまで正規表現を調整する。陰性側で1件でも誤検知したら、パターンを絞るか登録を見送る。`--good`は未指定だとエラーで弾かれる（goodは全ルール必須のため、`rules.jsonl`への登録前にこの実測段階で強制する）。
   </p>
7. **登録する**: 全てPASSしたら、以下の形式で1行JSONを`rules.jsonl`に追記する。
   ```json
   {"id": "<slug>-NNN", "pattern": "<正規表現>", "severity": "warn", "label": "<何が問題か>", "good": ["<書き直し例1>", "<書き直し例2>"], "scenes": ["business"], "enabled": true, "min_count": 1}
   ```

   - `id`: 既存の同系統ルールがあれば同じslugで連番、無ければ新しいslugを短い英字ケバブケースで作る。
   - **`severity`****は必ず****`"warn"`****で登録する**。`"critical"`への昇格は、このルールが実運用で複数回誤検知しないと確認できてから、チームの判断で別途手動で行う（正規表現ベースのStopフックは誤検知を強制力付きで残すと信頼を失いやすい）。
   - `scenes`: 特に指定が無ければ `["business"]`。
8. **報告する**: 登録した内容（id・パターン・実測結果）を短く報告する。次の書き込みから自動的に適用される。

## 登録しない場合

- 陽性の実例が手元に無い（「なんとなく気になる」レベルで具体的な文が示せない）: 実例が出るまで待つ。実例のない状態で作った正規表現は陰性側の検証しかできず、「検知/非検知を実測してから登録する」という規律に反する。
- 意図・文脈の判断が必要でレキシカルな正規表現に落とし込めない（例: 「頼んでいない対比で否定から入る」が語彙レベルでは「ではなく」という日常的に正当な表現と区別できない）: 正規表現ではなく、[良いgood例をCLAUDE.md](http://%E8%89%AF%E3%81%84good%E4%BE%8B%E3%82%92CLAUDE.md)等の指示ファイルに書き添える方向を提案する。

## Claude Code以外での利用

このSkillの仕組み自体はClaude Code固有（Skillという概念がツール依存）だが、手順自体は`ja_lint.py --test-rule`と`rules.jsonl`への追記だけなので、GitHub Copilot CLI / Cursor利用時も同じ手順を手動でなぞれば同じルールを登録できる。
