# データの形式

`<data-dir>` に次のファイルを配置する。`scripts/build.mjs` が形式と整合を検査し、`assets/template.html` へ埋め込んで単一の HTML を出力する。

| ファイル | 必須 | 内容 |
|---|---|---|
| `meta.json` | ○ | 題名、種別、用途、遷移の描画方法など |
| `machine.json` | ○ | 状態、枝、エラー、判定表 |
| `sections.json` | | 原文の節の一覧。枝の `src` が参照する |
| `issues.json` | | 原文の食い違い・記載のない点・作成者の注記。枝の `issue` が参照する |
| `timeline.json` | | 版の年表。存在する場合は `hist.json` も必要 |
| `hist.json` | | 版ごとの変更の一覧 |

`timeline.json` がない場合、ページは時点の移動・更新タブ・全履歴タブを表示せず、全ての枝の `h` は空でなければならない。`timeline.json` と `hist.json` の形式と、枝の `h` の規則は、この文書の末尾の「版の履歴」の節に記載する。

完成例:

| ディレクトリ | 内容 |
|---|---|
| `examples/fixture/` | 全項目を1件以上使用した最小の例。エンジンの検査用で、データの作り方の手本ではない |
| `examples/poteto-mode/` | 版の履歴を持つエージェント向けの指示書（Git 管理の Markdown、171コミット）。時点の再生、原文の節、指摘を使用する |

## meta.json

```json
{
  "title": "受付サーバ要件",
  "brand": "Example",
  "name": "受付サーバ",
  "source": { "title": "受付サーバ要件", "url": "https://docs.google.com/document/d/…/edit" },
  "anyLabel": "随時",
  "transitions": "explicit",
  "kinds": [["act", "動作", "act"], ["stop", "エラー・不可", "stop"], ["ticket", "整理券", "skill"], ["m", "値", "m"]],
  "variants": [{ "id": "web", "label": "Web 用" }, { "id": "device", "label": "端末用" }]
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | ○ | ページの題名。 |
| `slug` | | 閲覧者のブラウザに確認済みの記録と用途の選択を保存するキー。ページごとに一意にする。省略した場合は `title` を使用する。 |
| `brand` | | 左上に表示する名前。製品名やリポジトリ名を記載する。 |
| `name` | | 状態機械の枠の名前。原文の名前を記載する。 |
| `anyLabel` | | `any` の領域の名前。 |
| `source` | | 原文の題名と URL。左上の名前から原文へリンクする。 |
| `extract` | | `sections.json` の下書きを作成したコマンド。原文の取得・形式の変換を含め、実行順に改行で区切って記載する。ローカルのパスは `<原文>` などの仮の名前に置換する。追従の際に、同じ節の集合を再現するために使用する。ページには表示しない。 |
| `transitions` | | 状態間の接続の描画方法。`"flow"`（既定）は `flow` の状態を配列の順に暗黙に接続する。`"explicit"` は暗黙の接続を描画せず、遷移先 `["state", 状態名]` を持つ枝から、その状態へ矢印を描画する。 |
| `kinds` | | 遷移先の種別の定義。`[ID, 表示名, 外観]` の配列。外観は組み込みの `skill` `prin` `pb` `act` `stop` `m` のいずれかで、色・形・補足の表示方法を引き継ぐ。ID は `^[a-z][a-z0-9_-]*$` で、`state` は使用できない。組み込みの ID は定義しなくても使用できる。 |
| `legend` | | 凡例。`[種別, 表示名]` の配列。省略した場合、`kinds` から作成する。 |
| `variants` | | 用途の一覧。`{ "id", "label" }` の配列。定義した場合、全ての枝・エラー・判定表の記載済みの欄に `for` が必要になる。 |
| `levelLabels` | | 要求の強さの表示名の上書き。例: `{ "should": "望ましい" }`。 |
| `repoUrl` `link` | | 版へのリンク。`timeline.json` がある場合に使用する。`link` は `{ "commit": "…/commit/{sha}", "pr": "…/pull/{pr}" }` の形で、指定した場合は `repoUrl` より優先する。`link.pr` がない場合は、`pr` を持つ版もコミットへリンクする。`timeline.json` があり、どちらもない場合はエラーとする。 |
| `areas` | | 変更の区分。`hist.json` の各変更が番号で参照する。原文の節の構成から決定する。`hist.json` がある場合は必須。 |
| `file` `fileLabel` | | 原文のパスと、全履歴の絞り込みとカードの見出しに表示する短い名前。 |
| `series` | | 全履歴の図に重ねる件数の推移。「版の履歴」の節を参照。 |

`transitions` が `"flow"` のときに遷移先 `["state", …]` を使用した場合はエラーとする。

## machine.json

```json
{
"flow": [
  { "state": "受付",
    "rules": [
      {"g":"パラメータの検証を通過","to":[["state","審査"]],"for":["web","device"]},
      {"g":"POST リクエスト","to":[["act","受け付ける"]],"for":["web"],"src":"t.0/h.post"}
    ],
    "errors": [
      {"g":"POST リクエスト","to":[["stop","受け付けない"]],"for":["device"],"src":"t.1/h.post"},
      {"g":"id なし","to":[["stop","エラー"]],"for":["web"],"src":"t.0/h.id","inferred":"原文は「必須」とだけ記載し、違反時の結果を記載していない"},
      {"g":"日付が ISO 8601 の形式でない","to":[["stop","エラー"]],"for":["web"],"src":"t.0/h.date","std":["eq","ISO 8601 のとおり"]}
    ]
  }
],
"any": []
}
```

- `flow`: 作業の局面。配列の順に左から右へ配置する。1件以上が必要。
- `any`: 契機で発火する状態。下段へ配置する。空の配列でもよい。

### 状態

| 項目 | 必須 | 内容 |
|---|---|---|
| `state` | ○ | 状態の名前。全体で一意にする。 |
| `code` | | `true` の場合、名前を等幅で表示する。 |
| `rules` | | 枝の配列。正常系と、要求の拒否ではない結果（「取り消せない」「発行しない」など）を記載する。 |
| `errors` | | 要求の拒否（エラー・受け付けない）の枝の配列。状態の下部に「エラー・不可」の件数として折り畳んで表示する。同じ `to` を持つ枝は、条件を並べて1つの遷移先へまとめて表示する。時点・用途の強調や選択の対象を含む場合は自動で開く。 |
| `table` | | 判定表。次の節を参照。 |

`rules`・`errors`・`table` のうち、少なくとも1つが空でない必要がある。

### 枝

`rules` と `errors` の要素。判定表の記載済みの欄も同じ属性を持つ（`g` を除く）。

| 項目 | 必須 | 内容 |
|---|---|---|
| `g` | ○ | 条件。体言止めの短い句。 |
| `to` | ○ | 遷移先の配列。複数の場合は順に矢印で接続する。 |
| `for` | △ | 適用する用途の ID の配列。`meta.variants` を定義した場合は必須で、空にできない。 |
| `src` | | 根拠となる原文の節の ID。空白区切りで複数指定できる。 |
| `why` | | 根拠となる規格・方針。文字列、または `[短い名前, 詳細]`。短い名前を印として表示し、詳細はホバーで表示する。 |
| `level` | | 要求の強さ。`must`（既定、印なし）、`should`（望ましい）、`may`（任意）、`deferred`（当面実装しない）、`trial`（試験的）。 |
| `std` | | 標準との関係。`[種類, 説明]` または `[種類]`。種類は `eq`（標準どおり）、`strict`（標準より厳格）、`dev`（標準からの逸脱）。説明には標準の規定を記載する。 |
| `inferred` | | 作成者が補った箇所であることと、その理由。原文が明記していない結果や条件を記載した場合に必ず付ける。空文字は不可。 |
| `issue` | | 関係する指摘の ID。空白区切り。 |
| `h` | | 版との対応付け。`timeline.json` がある場合だけ使用できる。「版の履歴」の節を参照。 |
| `gap` | | `true` の場合、この枝の前に間隔を追加する。 |

### 遷移先

遷移先は `[種別, 表示名]` または `[種別, 表示名, 補足]` である。

- 種別は、組み込みの `skill` `prin` `pb` `act` `stop` `m`、`meta.kinds` で定義した ID、または `state` のいずれか。
- `["state", 状態名]` は、その状態への遷移を表す。状態名は `machine.json` に存在する必要がある。`meta.transitions` が `"explicit"` の場合だけ使用できる。遷移先の配列の末尾に置く。
- 補足の表示は、外観（`kinds` の3番目、組み込みの場合は種別そのもの）に従う。`pb` は表示名の右に小さく表示し、それ以外の外観はホバーで表示する。

### 判定表

条件が2つの軸の組み合わせで決まる規定を、表で表示する。軸が3つ以上ある場合は、行または列の値に組み合わせを記載する（例: 「会員・期限の設定あり」）。

```json
"table": {
  "rows": { "label": "利用者", "values": ["非会員", "会員・期限の設定あり", "会員・期限の設定なし"] },
  "cols": { "label": "契機", "values": ["発行時", "使用時"] },
  "cells": [
    { "r": 0, "c": 0, "to": [["m", "1 日"]], "for": ["web"], "src": "t.0/h.expiry" },
    { "r": 2, "c": 1, "issue": "i2" },
    { "r": 1, "c": 0, "na": "原文は期限の設定がある場合を発行時の規定に含めていない" }
  ]
}
```

| 欄の記載 | 意味 | 表示 |
|---|---|---|
| `to` を持つ | 原文に記載がある | 遷移先を表示する |
| `na` を持つ（文字列） | 該当しない組み合わせ | 「—」を表示し、`na` の内容をホバーで表示する |
| `to` も `na` も持たない、または欄を記載しない | 原文に記載がない（未規定） | 「未規定」を警告の色で表示する |

- `r` と `c` は 0 始まりで、`values` の範囲内にする。
- 1つの要素に `to` と `na` の両方を記載することはできない。
- 同じ欄に `to` を持つ要素を複数記載できるのは、`for` が互いに重ならない場合だけである。この検査は時点を考慮しないため、版の履歴で欄の値が置き換わった場合は、要素を削除と追加に分けず、1つの要素の `h` に `c` を記載する。
- 該当しない欄と未規定の欄の `for` は任意で、用途の絞り込みにだけ使用する。これらの欄は、状態を表示する根拠にならない。
- 用途を選択したとき、ある欄の記載済みの要素が全てほかの用途向けの場合は、「—」（この用途には該当しない）を表示する。
- 欄の一部だけを未規定にすることはできない。結果の一部だけが記載されている場合は、列（または行）を結果の項目ごとに分割する（例: 「使用時の有効期限」と「使用時の新しい整理券」）。
- 未規定の欄に `issue` を付けると、指摘への移動ができる。`issue` のない未規定の欄は、build が注記として出力する。

## sections.json

原文の節の一覧。最新版の原文だけを記載する。次のスクリプトで下書きを作成できる。

| 原文 | スクリプト | 節の ID |
|---|---|---|
| Google Docs（MCP の `read_doc` の出力） | `jq -f scripts/extract-gdoc.jq <出力.json>` | `<タブ ID>/<見出し ID>`。冒頭は `<タブ ID>/top`。子タブも抽出する |
| Markdown | `node scripts/extract-md.mjs <file.md> [--url <URL>] [--tab <分類>] [--items] [--arrows] [--ids]` | 見出しの経路のスラッグ（例: `playbooks/investigation`）。`--items` は太字の見出し語で始まる項目を、`--arrows` は「条件 → 動作」の箇条書きを、`--ids` は ID で始まる箇条書き（`- R5-1: 本文`）を、下位の節に分割する。項目のスラッグは題の先頭の8語（語の区切りがない題は先頭の24文字） |
| そのほかの形式（org-mode、Word、HTML など） | `pandoc -f <形式> -t gfm --wrap=none` で Markdown へ変換し、上の行のスクリプトを使用する | 同上 |

節の ID は、原文の位置ではなく見出しから作成する。原文の更新後に再抽出しても、既存の `src` は同じ節を指す。見出しの文言が変更された節は ID が変化するため、追従の際に `src` を置換する。

```json
[
  { "id": "t.0/h.id", "tab": "Web 用", "level": 3, "title": "id パラメータを必須とする", "url": "https://docs.google.com/document/d/…/edit?tab=t.0#heading=h.id", "text": "id は3文字以上とする。" },
  { "id": "t.2/h.refs", "tab": "総論", "level": 3, "title": "References", "url": "…", "text": "…", "skip": "参考文献の一覧で、規定を含まない" }
]
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 一意の ID。`src` が参照する。重複は build のエラーとする。 |
| `title` | ○ | 見出し。 |
| `text` | ○ | 原文の本文。空文字の節は見出しだけの節として扱う。 |
| `tab` | | 原文のタブなどの分類。一覧の見出しに使用する。 |
| `level` | | 見出しの階層。 |
| `url` | | 原文の該当箇所への URL。 |
| `skip` | | 網羅の検査から除外する理由。 |

網羅の検査: `text` が空でなく `skip` を持たない節は、少なくとも1つの枝・エラー・判定表の欄の `src` から参照されなければならない。参照されない節がある場合、build はエラーとする。

版の履歴がある場合:

- 節は最新版の原文だけを持つ。過去の時点の文面は、更新タブの変更前・変更後で確認する。
- 削除済みの枝（`h` に `d` を持つ枝）は、`src` を持たなくてよい。持つ場合は、最新版に同じ見出しが残っている節だけを指定する。

`sections.json` がある場合、build は `src` を持たない枝（削除済みを除く）の件数を出力し、1件以上あれば注記として位置を出力する。

ページでは「原文」タブに節を `tab` ごとに表示する。節を選択すると本文を展開し、その節を `src` に持つ枝へ移動する。枝を選択すると、その枝の `src` の節を表示する。

## issues.json

```json
[
  { "id": "i1", "type": "conflict", "title": "`ticket_id` と `ticketId` の表記の食い違い", "body": "受付の節は `ticket_id`、発行の節は `ticketId` と記載している。", "src": "t.0/h.reception t.0/h.issue" }
]
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 一意の ID。 |
| `type` | ○ | `conflict`（原文の食い違い）、`gap`（記載のない点）、`ambiguous`（解釈が分かれる記載）、`note`（作成者の注記。配置の変更など）。 |
| `title` | ○ | 短い題。 |
| `body` | ○ | 内容。 |
| `src` | | 関係する原文の節の ID。空白区切り。 |

ページでは「指摘」タブに一覧を表示する。指摘を選択すると、その指摘を `issue` に持つ枝と欄へ移動する。

## 用途の表示

`meta.variants` を定義した場合、ページの上部に「すべて」と各用途の絞り込みを表示する。

- 「すべて」では、全ての用途に適用されない枝に、適用する用途の印を表示する。
- 用途を選択すると、その用途を `for` に持たない枝・欄を非表示にし、表示する枝を持たない状態を非表示にする。

## 検査の一覧

build は次の場合にエラーとし、HTML を出力しない。

- 必須の項目がない。値の種類が不正。
- 状態の名前が重複している。`rules`・`errors`・`table` が全て空の状態がある。
- 遷移先の種別が未定義。`["state", …]` の状態が存在しない。`transitions` が `"flow"` なのに `["state", …]` を使用している。
- `variants` を定義しているのに `for` がない枝・欄がある。`for` に未定義の用途がある。
- 節の ID が重複している。`src` に存在しない節がある。`issue` に存在しない指摘がある。
- 網羅の対象の節が、どこからも参照されていない。
- `level`・`std`・`issues[].type` の値が定義外。`inferred` が空文字。
- 判定表の `r`・`c` が範囲外。同じ欄で `for` が重なる。1つの要素に `to` と `na` の両方がある。
- `hist.json` だけがあり、`timeline.json` がない。`hist.json` に変更が空の版がある（原文の移動だけの版は「原文の移動」の変更を1件記載する）。
- `timeline.json` がないのに `h` を持つ枝がある。`h` が「版の履歴」の節の規則に違反している。

build は次の情報を出力する。

- 状態・枝・エラー・判定表の欄の件数
- 未規定の欄の一覧（`issue` の有無を含む）
- `inferred` を持つ枝の件数
- 節の網羅の結果と、`src` を持たない枝（削除済みを除く）の件数
- `transitions` が `"explicit"` の場合: 用途ごと（用途がない場合は全体）の到達性。`flow` の先頭の状態から `["state", …]` の遷移で到達できた状態の件数と、その用途の枝を持つ `flow` の状態の件数（`到達 (<用途>): 到達 / 対象`）。到達できない状態は注記として出力する。版の履歴がある場合は、最新版で存在する枝（`d` を持たない枝）だけを対象にする
- 版の履歴がある場合: 版の件数、対象ファイルを変更した版の件数、変更の件数と枝に対応した件数、枝に対応しない版の一覧

## 版の履歴

### timeline.json

範囲内の全ての版を、新しい順に記載する。

```json
[
  {"sha":"bf0c7cd80a","date":"2026-11-15","ver":"0.15.42","type":"f","add":748,"del":2061,"title":"既定モデルを変更、`/why` と `/how` を1ファイルへ縮小","pr":1236,"star":true},
  {"sha":"3c0fdb4e76","date":"2026-10-23","ver":"0.15.31","type":"f","add":54,"del":0,"title":"ketchup-video スキルを追加","pr":797,"tags":[["skill","ketchup-video"]],"star":true}
]
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `sha` | ○ | 版の ID。7〜40文字の16進数。全ファイルで同じ長さに統一する。 |
| `date` | ○ | `YYYY-MM-DD`。 |
| `title` | ○ | 件名。読み手の言語で記載する。バッククォートで囲んだ部分は等幅で表示する。 |
| `add` `del` | ○ | 追加・削除の行数。 |
| `ver` | | その時点のバージョン。ない場合は空文字。 |
| `type` | | `c` はバージョンの更新だけの版で、薄く表示する。ほかの値（`f` 機能、`x` 修正、`d` 文書、`r` 整理、`t` テスト）は記録用。 |
| `pr` | | PR の番号。 |
| `tags` | | その版で追加・削除された名前付きの単位。`[種別, 名前]`、削除は `[種別, 名前, true]`。種別は `skill`・`prin`・`pb` のいずれかで、全履歴の色に使用する。 |
| `star` | | 注目の版に `true`。 |

`meta.series` は、全履歴の図に重ねる件数の推移（2本まで）。`k` は `tags` の種別（複数の場合は配列）、`start` は初版より前の件数。

### hist.json

対象ファイルを変更した版ごとに、変更の配列を記載する。キーは `timeline.json` の `sha` と一致させる。各変更は `[種別, 区分, 題, 変更前, 変更後]` である。

| 位置 | 内容 |
|---|---|
| 種別 | `a` 追加、`c` 変更、`d` 削除。 |
| 区分 | `meta.areas` の番号（0始まり）。 |
| 題 | 何が変化したかを示す短い題。識別子は原文のままバッククォートで囲む。 |
| 変更前 | 追加の場合は空文字。 |
| 変更後 | 削除の場合は空文字。 |

変更前と変更後は、条件と動作を省略せずに各1〜3文で記載する。配列内の順序が枝からの参照番号になるため、対応付けの後に順序を変更しない。対象ファイルの外の変更を記載する場合は、専用の区分（例: 「対象ファイルの外」）を `areas` に追加する。

### 枝の `h`

`h` は、空白で区切った対応の並びである。枝・エラー・判定表の記載済みの欄が持てる。

```
<sha>:<種別><番号>
```

- 種別: `a` その枝の規定を導入した、`c` 意味を変更した、`d` 削除した。枝から見た変化を表し、参照する `hist.json` の変更の種別と一致しなくてよい（既存の規定の変更で新しい枝が生じた場合、その枝の `a` は `hist` の `c` を参照する）。
- 番号: `hist.json` のその版の配列での位置（0始まり）。

規則:

- 対応を持つ枝は、追加（`a`）を1つ持つ。追加より前の版への対応は記載できない。
- 削除（`d`）は1つまでで、それより後の版への対応は記載できない。
- 同じ版への対応は1つまで。1つの版の複数の変更が同じ枝に関係する場合は、最も直接的な変更を指定する。
- `h` が空の枝は、全期間で表示される。

表示:

- 枝は、追加した版から削除した版までの期間に表示される。削除した版の時点では、取り消し線付きで表示される。
- 選択中の版に対応する枝は、種別に応じた色と記号（+ ~ −）で強調される。エラーの枝と判定表の欄も同様である。
- 選択中の時点より後に `c` を持つ枝は、⟳ 付きで薄く表示される。文面が最新版のものであることを示す。
- 表示される枝を持たない状態は、その時点では非表示になる。
