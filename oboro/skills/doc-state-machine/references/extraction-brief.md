# 変更の抽出の依頼文

対象ファイルを変更したコミットを束に分割し、束ごとにサブエージェントへ次の依頼文を渡す。`{...}` を置換する。出力先のファイルは束ごとに分割し、完了後に `hist.json` へ結合する。委任する条件（コミットの件数と差分の行数）は SKILL.md の手順6に記載している。`meta.json` の `areas` を先に決定し、文言の整理に使用する区分（例: 「その他」）を含める。

サブエージェントは依頼文だけを文脈として作業する。対象、目的、取得方法、出力の形式を省略しない。

## 依頼文

```
GitHub リポジトリ {OWNER}/{REPO} の `{FILE}` の変更履歴を読み取り、各コミットがこのファイルの
「規定の内容（この場合はこうする、という記載）」をどう変更したかを構造化して記録してください。
読み取り専用の調査です。成果物は JSON ファイル1つです。

## 目的
{原文の説明。例: エージェントの作業様式を定める指示書、業務システムの要件定義書} の全更新履歴を、利用者が1件ずつ確認できる
一覧にします。担当分のコミットについて、差分から「何が追加・変更・削除されたか」を正確に抽出します。
推測で補完せず、差分に記載のある内容だけを記録してください。

## 担当コミット（古い順）
{sha の一覧。初版を含む束では「初版。差分ではなく、この時点の全体の構成を記録」と付記する}

## 取得方法
{次の2つのうち、使用する方だけを記載する}

{GitHub の API を使用する場合}
- 差分: gh api "repos/{OWNER}/{REPO}/commits/<sha>" --jq ".files[] | select(.filename==\"{FILE}\") | .patch"
- 差分が空・欠落・途中で切れている場合は、前後の全文を取得して比較する:
  gh api "repos/{OWNER}/{REPO}/contents/{FILE}?ref=<sha>" -H "Accept: application/vnd.github.raw"
  親コミットは gh api "repos/{OWNER}/{REPO}/commits/<sha>" --jq ".parents[0].sha" で取得する。

{ローカルの clone を使用する場合}
- 差分: git -C {REPO_DIR} show <sha> -- {FILE}
- 差分が読み取りにくい場合は、前後の全文を比較する: git -C {REPO_DIR} show <sha>^:{FILE} と git -C {REPO_DIR} show <sha>:{FILE}
- リポジトリは読み取りだけとし、checkout・fetch・stash などの操作をしない。

- 初版は全文を取得して読み取る。

## 出力
次のパスへ JSON を書き出してください: {出力先のパス}

形式（担当コミットを古い順に全件）:
[
  { "sha": "<sha>", "changes": [
    { "k": "add", "area": "<区分>", "t": "題", "was": "変更前", "now": "変更後" }
  ] }
]

- k: add（新しい規定・項目の追加）/ chg（既存の規定の内容変更）/ del（規定・項目の削除）
- area: 次のいずれか。{meta.json の areas の一覧と、各区分の説明。文言の整理に使用する区分（例: 「その他」）を必ず含める}
- t: 何が変化したかを示す40字以内の題。スキル名・ファイル名・モデル名などの識別子は、
  原文のままバッククォートで囲む。
- was / now: 各1〜3文。規定の意味を要約する。原文の直訳である必要はないが、条件と動作を省略しない。
  追加の場合は was を、削除の場合は now を空文字にする。
- 1コミットに独立した変更が複数ある場合は、変更ごとに1要素に分割する。
- 意味の変化がない言い回しだけの修正（句読点、語順、短縮）は、コミットごとに1要素へまとめ、
  k は chg、area は文言の整理に使用する区分、t は「文言の整理」とする。
- 初版は、当時存在した節ごとに k: add で1要素ずつ記録する（now に項目の一覧を記載）。
- 文体: {読み手の言語と文体の指定}

## 完了時の返答
3行以内で、記録したコミット数、変更の総数、取得できなかったコミット（sha と理由）だけを記載してください。
```

## 結合

サブエージェントの出力を、`hist.json` の形式へ変換する。

- `k` を1文字にする（`add` → `a`、`chg` → `c`、`del` → `d`）。
- `area` を `meta.json` の `areas` の番号にする。
- 用語を統一する。束ごとに別のエージェントが記載するため、同じ概念に複数の語（例: slug と識別子、operator と運用者）が混在する。置換の対応表を作成し、全件へ適用する。
- 取得できなかったコミットがある場合は、そのコミットだけを再度委任する。

## 精度についての注意

サブエージェントの記載は、差分の読み取りの結果である。主セッションで全件を差分と照合しない場合は、最後の報告でその旨を示す。対応付け（`machine.json` の `h`）はこの記載から導出するため、同じ注意が対応付けにも及ぶ。
